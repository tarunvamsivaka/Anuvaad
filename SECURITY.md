# Security Policy

## Supported Versions

Currently, only the latest release on the `master` branch is supported with active security updates and patches.

| Version | Supported          |
| :------ | :----------------- |
| master  | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

We take the security of Anuvaad seriously. If you discover a security vulnerability, **please do NOT report it via a public GitHub issue, pull request, or public discussion.**

### Recommended Method: GitHub Private Vulnerability Reporting

Please submit your report confidentially via GitHub Private Vulnerability Reporting:
👉 **[Report a Vulnerability Confidentially](https://github.com/tarunvamsivaka/Anuvaad/security/advisories/new)**

### Alternative Method: Direct Security Email

If you cannot access GitHub Advisories, email the repository maintainer directly:
- **Contact**: Tarun Vamsi Vaka
- **Email**: `tarunvamsivaka@gmail.com`
- **Subject Line**: `[SECURITY VULNERABILITY] Anuvaad - <Brief Description>`

### What to Include in Your Report

To help us triage and resolve the issue quickly, please provide:
1. **Description**: A clear description of the vulnerability and its potential impact.
2. **Affected Component**: Specific file, API route, or infrastructure service affected.
3. **Reproduction Steps**: Step-by-step instructions or minimal proof-of-concept (PoC).
4. **Proposed Fix (Optional)**: Any suggestions or mitigation strategies you have identified.

---

## Response Commitments & SLA

- **Initial Acknowledgement**: Within 24 to 48 hours of receipt.
- **Triage & Assessment**: Within 5 business days.
- **Patch & Advisory Release**:
  - **Critical / High Severity**: Within 14 business days.
  - **Medium / Low Severity**: In the next scheduled release cycle.

---

## Safe Harbor Policy

We consider security research conducted under this policy to be:
- Authorized under applicable anti-hacking laws.
- Exempt from restrictions on reverse engineering or circumvention in our Terms of Service.
- Lawful and conducted in good faith.

Please do not access, modify, or delete user data, degrade system availability (e.g., DoS attacks), or disclose vulnerabilities publicly before a patch has been released.
